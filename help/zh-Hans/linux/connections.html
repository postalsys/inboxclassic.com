Inbox Classic 建立的连接

Inbox Classic 连接到哪里以及原因，供想了解技术细节的用户参考。

  • 您的邮件服务器，通过 IMAP 读取邮件，通过 SMTP 发送邮件。连接使用 TLS 加密，并根据系统信任的证书检查每个服务器的证书。Inbox Classic 会拒绝没有加密的服务器，除非您选择无（不加密）并确认。
  • 添加帐户时，查找其服务器。Inbox Classic 通过 DNS over HTTPS（先 Cloudflare，后 Google）查询您域的 MX 和 SRV 记录。它还会尝试您的提供商的自动配置文件和 Thunderbird 的提供商列表（ISPDB）。对于 Exchange，它会询问 Microsoft Autodiscover，只有当 Autodiscover 通过 HTTPS 要求时才会向其提供您的密码。从不选择没有加密的服务器。
  • 浏览器登录，使用 OAuth 2.0 和 PKCE 连接到 Google、Microsoft 或您的登录应用的提供商。浏览器只会返回到这台计算机上的 Inbox Classic。
  • 品牌徽标（BIMI），当邮件本身没有可用的徽标且没有可重复使用的已保存副本时，从品牌的 HTTPS 地址获取。下载的徽标会缓存，应用重启后仍可使用。只有当您的邮件服务器认定邮件通过了 DMARC 检查并认可该徽标时，才会这样做。
  • 来自 Internet 的图片，在您允许时下载，包括通过受信任的发件人或自动下载设置允许的情况。
  • 退订，仅在您批准后进行。一键退订请求（RFC 8058）要求邮件带有您的邮件服务器认可的 DKIM 签名，并且该签名涵盖两个退订标头。
  • 加密密钥，在需要收件人的密钥或您开始查找时获取。按地址搜索时会查询该地址的域（Web Key Directory），如果已启用，再查询 keys.openpgp.org。按指纹或密钥 ID 搜索时，会将该标识符而不是地址发送到 keys.openpgp.org。发布您的公钥会将其发送到 keys.openpgp.org，并请求确认其中的地址。

只有当您的提供商报告验证码所属的域或其上级域有有效的 DKIM 签名时，才会提供验证码。Inbox Classic 从提供商的 Authentication-Results 或 ARC-Authentication-Results 标头中读取此结果，不需要单独建立连接。
