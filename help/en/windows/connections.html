The connections Inbox Classic makes

Where Inbox Classic connects, and why, for the technically curious.

  • Your mail servers, over IMAP to read mail and SMTP to send it. Connections are encrypted with TLS, and each server’s certificate is checked against those your system trusts. Inbox Classic refuses a server without encryption, unless you choose None (unencrypted) and confirm.
  • When you add an account, to look up its servers. Inbox Classic reads your domain’s DNS records through DNS over HTTPS (Cloudflare, then Google), never plain DNS. It also tries your provider’s autoconfig file and Thunderbird’s list of providers (ISPDB). For Exchange, it asks Microsoft Autodiscover, which gets your password only when it asks for it over HTTPS. A server without encryption is never picked.
  • Browser sign-in, with OAuth 2.0 and PKCE, to Google, Microsoft or the provider of your sign-in app. The browser returns to Inbox Classic on this computer only.
  • Brand logos (BIMI), from the brand’s HTTPS address when the message does not carry the logo, once each time Inbox Classic runs. This happens only when your mail server passed the message’s DMARC check and approved the logo.
  • Pictures from the internet, only when you ask for them.
  • Unsubscribe, only when you click it. A one-click request (RFC 8058) is sent only when the list signed the message with DKIM.

Sign-in codes are offered only when your provider’s Authentication-Results header says the domain signed the message (DKIM). This needs no connection of its own.
