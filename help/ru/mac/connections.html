Подключения Inbox Classic

Куда подключается Inbox Classic и зачем: для тех, кому интересны технические подробности.

  • Ваши почтовые серверы: по IMAP для чтения почты и по SMTP для отправки. По умолчанию соединения защищены с помощью TLS, а сертификат каждого сервера проверяется по сертификатам, которым доверяет ваша система. Inbox Classic отказывается работать с сервером без шифрования, если только вы не выберете Нет (без шифрования) и не подтвердите выбор.
  • При добавлении учетной записи, чтобы найти ее серверы. Для поиска настроек Inbox Classic запрашивает записи MX и SRV домена через DNS over HTTPS (Cloudflare, затем Google). Для подключения к найденным серверам используется системное разрешение имен. Программа также проверяет файл автонастройки провайдера и список провайдеров Thunderbird (ISPDB); запрос автонастройки может содержать ваш адрес электронной почты. Для Exchange программа обращается к Microsoft Autodiscover, который получает ваш пароль, только если запрашивает его по HTTPS. Сервер без шифрования никогда не выбирается.
  • Вход через браузер с OAuth 2.0 и PKCE в Google, Microsoft или к провайдеру вашего приложения для входа. После входа браузер передает результат только в Inbox Classic на этом компьютере.
  • Логотипы брендов (BIMI): с HTTPS-адреса бренда, если логотипа нет в самом сообщении и подходящей копии нет в локальном кеше. Копии сохраняются между запусками и обновляются через 30 дней; после неудачной загрузки повторная попытка возможна через сутки. Это происходит, только если ваш почтовый сервер подтвердил прохождение проверки DMARC и одобрил логотип.
  • Изображения из интернета: по вашему запросу или согласно настройкам автоматической загрузки. Для зашифрованных частей сообщения каждый раз требуется явное разрешение.
  • Отписка: только по вашему запросу. Запрос в один щелчок (RFC 8058) отправляется только после подтверждения и при доверенном результате проверки DKIM, подтверждающем подпись обоих заголовков отписки.
  • Ключи шифрования: при шифровании сообщения для получателя, чей ключ еще не сохранен, и при поиске ключа вручную. Поиск по адресу сначала обращается к домену получателя (Web Key Directory), затем к keys.openpgp.org, если эта возможность не отключена; передается адрес получателя. При поиске ключа подписи по вашему запросу на keys.openpgp.org передается отпечаток или идентификатор ключа. При публикации вашего ключа этому серверу передаются его открытая часть и адреса для подтверждения.
  • Обновления: с inboxclassic.com, чтобы узнать, вышла ли новая версия, если включена проверка обновлений.

Коды для входа предлагаются, только если доверенный заголовок Authentication-Results / ARC-Authentication-Results провайдера подтверждает подпись DKIM домена, к которому относится код, или его родительского домена. Для этого отдельное подключение не нужно.
