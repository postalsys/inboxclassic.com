De verbindingen die Inbox Classic maakt

Een technisch overzicht van de netwerkverbindingen die Inbox Classic gebruikt.

  • Je mailservers, via IMAP om mail te lezen en via SMTP om mail te verzenden. Verbindingen zijn versleuteld met TLS, en het certificaat van elke server wordt gecontroleerd met de certificaten die je systeem vertrouwt. Inbox Classic weigert een server zonder versleuteling, tenzij je Geen (niet versleuteld) kiest en dat bevestigt.
  • Als je een account toevoegt, om de servers op te zoeken. Inbox Classic zoekt de MX- en SRV-records van je domein via DNS over HTTPS (Cloudflare, daarna Google). Voor gewone serververbindingen wordt wel de DNS-resolutie van het systeem gebruikt. Het probeert ook het autoconfig-bestand van je provider en de providerlijst van Thunderbird (ISPDB). Bij autoconfig kan je e-mailadres naar de server met de instellingen worden gestuurd. Voor Exchange gebruikt het Microsoft Autodiscover, dat je wachtwoord voor HTTP Basic-aanmelding kan ontvangen als het daar via HTTPS om vraagt. Een server zonder versleuteling wordt nooit gekozen.
  • Aanmelden via de browser, met OAuth 2.0 en PKCE, bij Google, Microsoft of de provider van je aanmeldapp. De browser stuurt het resultaat terug naar Inbox Classic op deze computer.
  • Merklogo’s (BIMI), vanaf het HTTPS-adres van het merk als het logo niet is meegestuurd en er geen opgeslagen kopie kan worden gebruikt. Gedownloade logo’s worden opgeslagen en opnieuw gebruikt, ook nadat het programma opnieuw is gestart. Dat gebeurt alleen als je mailserver een geslaagde DMARC-controle heeft gemeld en het logo heeft goedgekeurd.
  • Afbeeldingen van internet, alleen als je daarvoor toestemming hebt gegeven.
  • Afmelden, alleen na je bevestiging, ook als een agent het verzoek voorstelt. Een verzoek met één klik (RFC 8058) wordt alleen verzonden als je mailprovider een DKIM-handtekening heeft goedgekeurd die beide afmeldheaders omvat.
  • Sleutels voor versleuteling worden opgezocht als bij het versleutelen een sleutel van een ontvanger ontbreekt of als je zelf een sleutel opzoekt. Bij zoeken op e-mailadres vraagt Inbox Classic eerst het domein van dat adres om de sleutel (Web Key Directory). Zo nodig wordt het adres daarna naar keys.openpgp.org gestuurd, als die zoekfunctie is ingeschakeld. Bij zoeken op vingerafdruk of sleutel-ID wordt deze naar keys.openpgp.org gestuurd, zonder e-mailadres. Bij het publiceren wordt je openbare sleutel naar keys.openpgp.org gestuurd en wordt om bevestiging van de e-mailadressen gevraagd.
  • Updates, van inboxclassic.com, wanneer je op updates controleert of automatische controles aanzet.

Aanmeldcodes worden alleen aangeboden als je provider een geldige DKIM-handtekening bevestigt van het domein waarvoor de code bedoeld is of van een bovenliggend domein. Inbox Classic leest dit resultaat uit de Authentication-Results- of ARC-Authentication-Results-header van je provider. Daarvoor is geen aparte netwerkverbinding nodig.
